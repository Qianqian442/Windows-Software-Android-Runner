# Windows Software Android Runner

独立 Android 项目：从 QQ、微信或文件管理器接收 Windows 安装包，并在 Android 设备上管理 Windows 兼容运行环境。

## 目标体验

1. 从 QQ/微信/文件管理器选择或分享 `.exe`、`.msi`、`.zip` 等文件到本应用。
2. 检查文件类型、CPU 架构、安装器元数据和依赖线索。
3. 为每个 Windows 程序建立隔离的兼容环境（prefix/container）。
4. 在获得用户确认后下载并配置所需组件。
5. 在兼容环境中执行安装程序，并为可启动程序创建应用内快捷入口。
6. 管理、备份、恢复和移除程序及其环境。

## 重要技术边界

Android 不能原生安装或执行 Windows PE 程序。真正运行 Windows 软件需要集成并维护兼容运行时、CPU 指令翻译层、Windows API 实现及图形/音频输入输出适配。某些程序依赖 Windows 内核驱动、专用硬件、反作弊或厂商授权机制，无法保证在 Android 上运行。

本项目不会伪造硬件机器码、绕过软件授权或承诺所有 Windows 程序 100% 兼容。授权检查应使用软件厂商允许的方式。

## 分阶段路线

- **阶段 1：Android 外壳与导入**：接收 Android 分享 Intent、文件选择、文件信息与安全提示。
- **阶段 2：运行时管理**：设备 ABI/GPU 能力检测、兼容运行时下载与校验、隔离环境管理。
- **阶段 3：安装工作流**：安装器识别、依赖检测、用户确认、运行日志与错误诊断。
- **阶段 4：程序启动与桌面入口**：应用内启动器、窗口/输入/音频适配、快捷入口。
- **阶段 5：兼容性扩展**：按软件类别建立测试矩阵，逐项提升支持范围。

## 安全要求

- 不自动执行刚导入的未知文件；先显示来源、文件名、大小和校验信息并要求用户确认。
- 运行时和依赖组件必须来自可验证的可信来源，记录版本与 SHA-256。
- 不请求 root 权限作为默认前提。
- 每个 Windows 程序使用独立数据目录，避免互相污染。
- 不将用户安装包上传到服务器；默认仅在本机处理。

## 当前状态

当前提交仅建立 Android 项目骨架和安装包导入入口；尚未集成 Wine/Box64 等 Windows 兼容运行时，因此当前版本不能安装或运行 Windows 程序。
